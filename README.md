# 机械动力服务器：从选配置到防卡顿，3人小服和10人联机分别怎么买不亏

开一个机械动力服务器，最容易踩的坑不是"买贵了"，而是买错了方向。很多人看到"整合包"三个字，第一反应是核心数往高了堆，8核16核安排上，结果传动轴一转、火车一开、挖矿机一挂机，TPS 还是往下掉。

问题出在机械动力（Create）这个模组的计算方式上。它的齿轮、传动轴、移动装置、列车时刻都在跑物理和方块交互运算，而这些运算几乎全压在 Minecraft 服务端的主线程上。主线程跑在主频最高的那一个核上，剩下的核在旁边看着。所以对机械动力服务器来说，**主频和单核性能比核心数量重要得多**。

这篇文章解决三件事：机械动力服到底要什么配置、雨云游戏云现在有哪些档位和价格、开起来之后怎么调才不卡。

## 机械动力服务器难在哪儿：卡的不是人数，是装置数量

普通生存服扩容的逻辑是"人多了加配置"。机械动力服不完全是这样。

一个玩家搭的超大型自动化产线，可能比 20 个只盖房子的玩家更吃性能。原因很直接：每一个正在运转的装置，每一节移动的机械臂，每一列在路上跑的火车，都在给服务端 tick 增加工作量。掉落物堆在地上没人捡、传送带末端没有收集箱、物品在无限循环里兜圈子，这些都会实打实地吃掉 TPS。

所以判断"我该买多大配置"，不能只数人数，还得看你打算怎么玩：

- 就三四个人，搭搭风车、水车、简单传送带 —— 需求比想象中低
- 有人专门造重工业产线、无人矿机、全自动农场 —— 需求陡增
- 玩的是 200+ mod 的机械动力整合包，还带航空学、Create: Additions 这类扩展 —— 直接按重负载算

## 开服前先算账：机械动力服务器需要多少内存

内存是第二条硬指标。机械动力本身吃内存，加上整合包里塞的其他模组、每位玩家加载的区块，数字很快就上去了。综合几个公开的服主向资料，可以给出这样一张参考表：

| 同时在线人数 | 建议内存下限 | 建议内存 | 说明 |
| --- | --- | --- | --- |
| 1–3 人 | 4GB | 6GB | 4GB 能跑，世界生成和复杂装置时可能卡顿 |
| 3–5 人 | 6GB | 8GB | 小团体比较舒服的区间 |
| 6–10 人 | 8GB | 10–12GB | 人多 = 加载区块多、同时运转的机器多 |
| 10 人以上 / 重度自动化 | 12GB | 16GB | 大型整合包或大型工厂服务器 |

有些以机械动力为核心的整合包会直接把服务端内存配好。比如 Create: Aerospace 的服务端文件默认就给到 12GB，并注明这个量大概够 10 人同时游玩 —— 注意它的说明里还加了一句"不建议再往上加内存"。这条经验对机械动力服挺有用：**内存给够就行，堆太多反而让 GC 停顿变长**，卡顿未必更好。

CPU 这边记住一句话就够了：主频高、IPC 强、现代架构。老的 E5 系列核数看起来唬人，开机械动力整合包反而吃力。

## 开服与调优：几个真正影响体验的设置

选好机器之后，开服本身不算复杂。把机械动力跑顺，重点在下面这些地方。

**Java 版本别配错。** 1.20.1 的机械动力走 Forge + Java 17；1.21.1 走 NeoForge + Java 21。雨云面板的游戏类型下拉里选 "ForgeMod服"，NeoForge 也选这一项。有玩家记录的坑是：面板里选"游戏版本"时，容易把它理解成"最新的 mod 加载器版本"，结果装出来一个自己没打算玩的版本 —— 跟着你要玩的整合包版本走就行。

**服务端视距压下来。** 机械动力服的服务端视距设 5–8 就够了。视距每往上加一档，加载区块和装置运算量都跟着涨。雨云的官方承载数据也是按"MOD 服视距 5"这个基准给的。

**预生成区块。** 世界生成是 CPU 密集活儿。开服前用 Chunky 之类的工具把常用区域预生成好，比让玩家边跑图边生成流畅得多。

**改一下机械动力的服务端参数。** Create 的配置里有 `maxBlocksMoved`、`maxBlocksAttached` 这类限制单个装置一次能移动、连接多少方块的参数。默认值在大型装置上很容易拖垮 tick，适当调低是给服务器减负。

**给服里定几条规矩。** 掉落物必须有人捡、处理产线末端必须有收集箱、不允许无限循环的物品流。这几条不是洁癖，是最常见的 TPS 杀手。

**排查用 spark。** 卡了先别怀疑配置，用 spark profiler 看是哪个模组在吃 tick time，比盲猜快得多。

现在说一个具体案例，来自一位在雨云上开服的玩家自己的记录：3 个人玩机械动力 + 航空学，服务端约 50 个 mod，客户端不到 100 个，选的是 Platinum 8275CL 机型，日常造机器、开热气球跑图、挂机刷铁，没有遇到性能瓶颈，进服延迟通常在 30ms 左右。这个人一开始甚至还担心过带宽和内网穿透的问题，结论是独立 IP 或 NAT 映射都用不上穿透。当然这是 3 人的规模，人数翻倍就得重新算。

## 上线后卡了怎么办

按这个顺序排查，比自己瞎调快：

1. 看 TPS 掉到一个什么水平。轻微波动是正常的，持续掉到 15 以下就是真问题
2. 用 spark 定位是哪个模组、哪类实体在吃时间
3. 检查有没有溢出产线、地面掉落物、无收集的循环装置
4. 把服务端视距往下调一两档，看是否缓解
5. 检查内存分配是否偏低 —— 日志里出现 `OutOfMemoryError` 基本就是内存问题
6. 还不行就是硬件到顶了，升配

## 常见问题

**2核4G 能开机械动力吗？**
能开，但基本只够一两个人玩纯 Create 加少量辅助 mod。官方基准里 2核4G 承载的是"50 个 mod、视距 5"的 mod 服 6 人场景，而机械动力的物理运算比普通 mod 重。一旦出现自动化产线，就会开始掉 TPS。

**用面板服还是自己搭 VPS？**
第一次开服、不想碰命令行，选雨云面板或 MCSM 面板，一键开服，后面还能升级 CPU 和内存。想装多个服务端、要用 Windows、或者习惯自己控环境，选游戏云 VPS。

**一定要独立 IP 吗？**
不一定。MC 服走 NAT 映射的 15 个端口完全够用。独立 IP 主要是能开自定义端口的业务和方便直接分享地址。

**机械动力服务器会一直吃这么多性能吗？**
不会。日常挂着的时候消耗不高，压力来自玩家同时操作大型装置、跑图加载新区块、以及挂机时仍在运转的机器。这也是"动态计费"在机械动力场景里有点用的原因。

**能不能后期换 CPU 机型？**
雨云面板支持切换 CPU 机型，游戏云 VPS 支持随时升降配置。所以前期保守一点买，不是死局。
